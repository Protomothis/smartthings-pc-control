# v1.0.0 설계: 텔레그램 알림과 인바운드 제어

이 문서는 v1.0.0 마일스톤의 공용 설계 계약이다. 여러 작업자가 병렬로 구현하므로
**패키지 경계, 타입 이름, 설정 스키마, 이벤트 이름은 이 문서를 기준으로 맞춘다.**
바꿔야 하면 먼저 이 문서를 고치고 커밋한다.

## 1. 원칙

- 알림 발송 주체는 **서비스**다. 트레이 앱(gui)은 설정 화면과 테스트 버튼만 제공한다.
- Windows 토스트는 이 설계와 **무관**하다. 기존 유예 토스트는 그대로 유지한다.
- 텔레그램은 Bot API 아웃바운드(`sendMessage` 등)와 `getUpdates` 롱 폴링만 쓴다. 웹훅·포트 개방 없음.
- 설정은 기존 `config.json`에 추가하고 시크릿처럼 핫 리로드된다.
- 텍스트는 `parse_mode=HTML`. 템플릿은 `text/template` + 수동 `html.EscapeString`
  (`html/template`은 텔레그램이 모르는 엔티티를 만든다).

## 2. 패키지 배치

```
service/notify/      이벤트 정의, 버스, 카테고리 필터, 조용한 시간대, 스로틀, 집계   (이슈 #55 #58 #59)
service/telegram/    Bot API 클라이언트, 템플릿 렌더러, notify.Sink 구현, 인바운드 폴러 (이슈 #56 #57 #61 #62)
service/secret/      DPAPI 보호/해제                                                    (이슈 #65)
service/             기존 서버·WebUI. 이벤트 발생 지점에서 notify.Emit 호출, 설정 스키마, API (이슈 #55 #60 #63)
gui/                 알림 탭                                                            (이슈 #64)
```

`service/notify`와 `service/telegram`은 **`service` 패키지를 import하지 않는다** (순환 방지).
`service`가 둘을 import해서 조립한다. 로그는 두 패키지가 `func(format string, args ...any)` 형태의
로거를 주입받아 쓴다(`notify.SetLogger`, `telegram.Client.Log`).

## 3. 이벤트 카탈로그

`Category.Kind` 형태. 이 이름이 설정 JSON 키이자 템플릿 파일 이름이다.

| Category | Kind | 발생 지점 | Fields |
|---|---|---|---|
| remote | received | SmartThings 명령 즉시 실행 (유예 없음) | command, from |
| remote | grace_scheduled | 유예 예약 생성 | command, from, delay, execute_at |
| remote | grace_cancelled | 유예 취소 | command, by (toast/tray/app/webui/telegram/api) |
| remote | executed | 유예 만료 실행 | command |
| remote | force | forceshutdown 수신 | from |
| schedule | created | 앱/WebUI/텔레그램 예약 생성 | command, origin, delay, execute_at |
| schedule | cancelled | 예약 취소 | command, origin, by |
| schedule | executed | 예약 실행 | command, origin |
| schedule | replaced | 새 예약이 기존 예약 대체 | command, origin, old_command, old_origin |
| power | started | 서비스 시작 (부팅/WoL 복귀) | version, boot_time, external_ip |
| power | resumed | 절전 해제 (SERVICE_CONTROL_POWEREVENT / PBT_APMRESUMEAUTOMATIC) | since |
| power | stopping | 서비스 중지 직전 (SCM Stop/Shutdown) | reason |
| security | unauthorized | 잘못된 시크릿 요청 | from, path, count, window |
| security | login_limited | WebUI 로그인 실패 제한 발동 | from |
| security | unknown_command | 알 수 없는 명령 | from, command |
| security | config_changed | 시크릿/포트/원격접속/텔레그램 설정 변경 | keys, by |
| security | unknown_chat | 허용되지 않은 텔레그램 채팅의 명령 | chat_id, username, text |
| system | update_available | 새 릴리스 감지 (서비스가 24h마다 확인) | version, current, url |
| system | updated | 이전 실행 버전과 다름 (상태 파일 비교) | version, previous |
| system | exec_failed | 명령 실행 실패 | command, error |
| system | tray_wake_failed | 트레이 앱 깨우기 실패 | command, error |

`ping`은 어떤 카테고리에도 속하지 않는다. 절대 알리지 않는다.

## 4. `service/notify` 계약

```go
package notify

type Event struct {
    Category string            // "remote" ...
    Kind     string            // "grace_scheduled" ...
    At       time.Time
    Fields   map[string]string // 템플릿 변수. 값은 이미 사람이 읽을 형태(“5분”, “14:35:00”)
    Actions  []Action          // 인라인 버튼. 없으면 nil
}

type Action struct {
    Label string // 표시 문구 (이미 번역됨)
    Data  string // callback_data. 형식: "<verb>:<arg>" 예 "cancel:", "runnow:", "cmd:shutdown", "confirm:shutdown"
}

// Sink는 채널 하나(텔레그램 등)를 뜻한다.
type Sink interface {
    Send(ctx context.Context, ev Event) error
}

// Config는 config.json의 "notify" 객체. 카테고리별 Kind → bool.
type Config map[string]map[string]bool

func DefaultConfig() Config           // 3장 기본값. schedule.created/cancelled, power.stopping 은 false
func (c Config) Enabled(cat, kind string) bool  // 키가 없으면 DefaultConfig 값

type Bus struct { ... }
func New(opts Options) *Bus
type Options struct {
    Sink       Sink
    Config     func() Config           // 핫 리로드: 매 이벤트마다 호출
    Quiet      func() QuietHours       // 5장
    Now        func() time.Time        // 테스트용, nil이면 time.Now
    Log        func(string, ...any)
}
func (b *Bus) Emit(ev Event)          // 논블로킹. 큐(용량 256) → 워커 고루틴
func (b *Bus) Mute(d time.Duration)   // /mute
func (b *Bus) Unmute()
func (b *Bus) Close()
```

워커 파이프라인 순서: 카테고리 필터 → 집계(security.unauthorized, 6장) → 조용한 시간대/뮤트(5장) →
스로틀(채팅당 1건/초, 429의 `retry_after` 존중) → Sink.Send (실패 시 3회 지수 백오프 1s/4s/16s).
큐가 50건을 넘으면 오래된 것부터 같은 Category.Kind끼리 병합한다.

**항상 통과(조용한 시간·뮤트 무시)**: `remote.grace_scheduled`, `remote.force`. 사람이 취소할 기회이기 때문.
`security.*`는 `quiet_hours.security_bypass`가 true면 통과.

`service` 패키지에는 얇은 헬퍼를 둔다:

```go
// service/notify_wiring.go
var bus *notify.Bus
func emit(cat, kind string, fields map[string]string, actions ...notify.Action)
```

기존 `logMsg` 호출 지점 옆에 `emit`을 추가한다. 로그 문구는 바꾸지 않는다.

## 5. 조용한 시간대 (`QuietHours`)

```go
type QuietHours struct {
    Enabled        bool   `json:"enabled"`
    Start          string `json:"start"`            // "22:00" 로컬 시간
    End            string `json:"end"`              // "07:00" 자정 넘김 허용
    SecurityBypass bool   `json:"security_bypass"`  // 기본 true
    Digest         bool   `json:"digest"`           // 기본 true: 해제 시각에 요약 1통
}
```

조용한 시간 동안 걸러진 이벤트는 버리지 않고 모아 두고, 해제 시각(또는 `/unmute`)에
`system.digest` 이벤트 하나로 보낸다: Fields `count`, `period`, `items`(마지막 3건, 줄바꿈 구분).
`/mute 2h`는 같은 큐를 쓰는 임시 조용한 시간이다.

## 6. 보안 집계

`security.unauthorized`는 출처(from)별 첫 건은 즉시 보내고, 이후 같은 출처는 5분 창으로 묶어
`count`, `window`, `from`(출처 최대 3개 + "외 N곳")을 채워 한 건으로 보낸다.
`security.unknown_chat`도 같은 규칙, 창은 chat_id 기준.

## 7. `service/telegram` 계약

```go
package telegram

type Client struct { ... }              // http.Client 주입 가능(테스트)
func NewClient(token string, opts ...ClientOption) *Client
func (c *Client) GetMe(ctx) (User, error)
func (c *Client) SendMessage(ctx, chatID string, html string, kb *InlineKeyboard) (msgID int, err error)
func (c *Client) EditMessageText(ctx, chatID string, msgID int, html string, kb *InlineKeyboard) error
func (c *Client) AnswerCallbackQuery(ctx, id string, text string) error
func (c *Client) GetUpdates(ctx, offset int, timeoutSec int) ([]Update, error)
func (c *Client) SetMyCommands(ctx, cmds []BotCommand) error
// 429: RetryAfter 필드를 가진 *RateLimitError 반환. notify 스로틀이 이를 본다.

type Renderer struct { ... }            // 템플릿 렌더러
func NewRenderer(lang string, detail string) (*Renderer, error) // lang ko|en, detail simple|full
func (r *Renderer) Render(ev notify.Event, pcName string) (html string, err error)
// 템플릿은 //go:embed templates/<lang>/<category>.<kind>.tmpl. 없으면 generic.tmpl 로 폴백.
// 레이아웃(8장)을 지키고, 모든 Fields 값은 html.EscapeString을 거친다.

type Sink struct { ... }                // notify.Sink 구현
func NewSink(cli *Client, chatID string, r *Renderer, pcName string) *Sink
// Event.Actions → InlineKeyboard 한 줄. callback_data 는 그대로 전달.
// OnSent func(ev notify.Event, msgID int, html string) — sendMessage 성공 직후 동기 호출(Bus 워커 고루틴).
// service 는 remote.grace_scheduled 의 (chat_id, msgID, html) 을 활성 예약에 묶어 두고(#62, telegram_grace.go),
// 그 예약이 어떤 경로로든 끝나면(취소·실행·대체) 원문 + 결과 줄로 편집하고 키보드를 제거한다(15초 타임아웃, 최대 1회, 실패는 로그만).

type Poller struct { ... }              // 인바운드 (#61 #62)
func NewPoller(cli *Client, opts PollerOptions) *Poller
type PollerOptions struct {
    AllowedChatIDs func() []string        // 핫 리로드
    Handler        CommandHandler         // service 가 구현
    Log            func(string, ...any)
}
type CommandHandler interface {
    // 반환 html 은 답장. kb 가 있으면 인라인 키보드. 확인이 필요한 명령은 kb 로 [확인][취소] 를 돌려준다.
    HandleCommand(ctx, chatID string, cmd string, args []string) (html string, kb *InlineKeyboard, err error)
    // msgText 는 버튼이 달린 메시지의 평문(entities 제거). 편집 시 원문을 유지하는 데 쓴다.
    HandleCallback(ctx, chatID string, msgID int, msgText string, data string) (editHTML string, toast string, err error)
    Unauthorized(chatID, username, text string) // security.unknown_chat 발생용
}
// 선택 확장: Handler 가 EditKeyboarder 를 구현하면 HandleCallback 뒤의 editMessageText 에 그 키보드를 붙인다(confirm:<cmd> → [확인][취소]). 미구현 시 편집은 키보드를 제거한다.
type EditKeyboarder interface { EditKeyboard(data string) *InlineKeyboard }
func (p *Poller) Run(ctx) error         // 시작 시 offset을 마지막+1로 맞춰 과거 업데이트를 버린다
```

## 8. 메시지 레이아웃

```
{아이콘} <b>{제목}</b>
<blockquote>{핵심 한 줄}</blockquote>
{필드}: <code>{값}</code>          (detail=full 일 때만, 2~4개)
<i>{PC 이름} · {HH:MM:SS}</i>     (detail=full 일 때만)
```

아이콘: remote 🔌 · schedule ⏱ · power 🟢/🌙/🔴(started/resumed/stopping) · security 🛡 · system 🆕(update) ⚠️(오류) 📋(digest).
`remote.grace_scheduled` 에는 Actions `[바로 실행](runnow:)` `[취소](cancel:)` 가 붙는다.
버튼을 처리한 뒤에는 메시지를 편집해 원문을 유지한 채 결과 줄을 덧붙이고(`✅ 취소됨 · 14:32 · 텔레그램`) 키보드를 제거한다.
유예 메시지는 텔레그램이 아닌 경로로 끝나도 같은 방식으로 편집된다: `✅ 취소됨 · HH:MM · <by>`(토스트/트레이/앱/WebUI/API/텔레그램),
`▶️ 실행됨 · HH:MM · <by>`(타이머 또는 /now), `🔁 대체됨 · HH:MM`(새 예약이 덮어씀). 이미 끝난 예약의 버튼을 누르면 `⏹ 이미 처리됨` 을 덧붙이고 키보드만 제거한다.
`/menu` 의 `confirm:<cmd>` 는 메뉴 본문 아래에 확인 문구를 덧붙이고, `cancel:menu` 는 메뉴와 키보드를 유지한다.

## 9. 인바운드 명령

허용 Chat ID만 처리한다(`telegram.allowed_chat_ids`, 비어 있으면 `chat_id`). 미허용 채팅은 무시 + `security.unknown_chat`.
`control_enabled` 가 false 면 Poller 를 돌리지 않는다. 기본 false.
서비스 시작 전에 쌓인 업데이트는 버린다.

| 명령 | 동작 |
|---|---|
| `/status` | 버전, 가동 시간, 활성 예약(출처·남은 시간), 마지막 원격 명령 |
| `/menu` | 인라인 키보드: 잠금 / 화면 끄기 / 절전 / 재시작 / 종료 / 예약 취소 |
| `/lock` `/screenoff` | 즉시 실행 |
| `/sleep` `/hibernate` `/restart` `/shutdown` `[분]` | 분 없음: [확인][취소] 키보드 → 확인 시 **즉시 실행**(유예 없음). 분 있음: 예약(origin `telegram`) |
| `/cancel` | 활성 예약·유예 취소 (`by=telegram`) |
| `/now` | 활성 유예/예약 즉시 실행 |
| `/mute 2h` `/mute 30m` `/unmute` | Bus.Mute / Unmute |
| `/help` | 목록 |

`scheduleOrigin` 에 `originTelegram` 을 추가하고 문자열은 `"telegram"`. GUI 예약 탭은 이를 "텔레그램에서 요청"으로 표시한다.
`setMyCommands` 는 `control_enabled` 가 켜질 때 한 번 호출한다.

## 10. 설정 스키마 (`config.json` 추가분)

```json
"telegram": {
  "enabled": false,
  "bot_token": "dpapi:BASE64...",
  "chat_id": "",
  "control_enabled": false,
  "allowed_chat_ids": [],
  "detail": "full",
  "lang": "ko",
  "pc_name": "",
  "quiet_hours": { "enabled": false, "start": "22:00", "end": "07:00", "security_bypass": true, "digest": true }
},
"notify": { "remote": { "received": true, ... }, ... }
```

- `bot_token` 은 `dpapi:` 접두사 + Base64(DPAPI 머신 범위 암호문). 접두사가 없으면 평문으로 읽고 다음 저장 때 암호화한다.
  GUI 는 `/api/config` GET 에서 토큰을 **마스킹된 형태**(`****1234`)로만 받고, POST 에 토큰을 보낼 때만 교체한다
  (빈 문자열 또는 마스킹 값 그대로면 기존 유지).
- `pc_name` 비어 있으면 hostname.
- `lang` 은 GUI 언어 전환 시 함께 저장한다.
- `notify` 는 4장 `Config`. 키가 없는 항목은 기본값.

| 메서드 경로 | 동작 |

## 12. GUI 알림 탭 (`gui/notify_tab.go`)

탭 순서: 설정 / 명령 / 예약 / **알림** / 네트워크 / 로그. 아이콘 `theme.MailSendIcon()`.

1. **텔레그램 연결**: Bot Token(비밀 입력, 마스킹 값 표시), Chat ID, [Chat ID 찾기](→ `/api/telegram/chats`, 선택 대화상자), [테스트 발송], 상태 줄(`@bot_name` · 마지막 결과). BotFather 안내 힌트 + 하이퍼링크.
2. **텔레그램에서 제어**: 켬/끔, 허용 Chat ID 목록(Entry 한 줄에 쉼표 구분), 켜져 있으면 경고색 문구.
3. **받을 알림**: 카테고리 5개, 각각 마스터 체크 + 개별 체크(마스터 끄면 개별 비활성). [모두 켬] [모두 끔].
4. **조용한 시간대**: 켬/끔, 시작·종료 Select(30분 단위), 보안 예외, 요약 발송.
5. **표시**: 상세 수준 Select(간단/자세히). 언어는 앱 언어를 따른다는 힌트.
6. 저장 버튼은 기존 변경 감지 패턴(`cfgBaseline`)을 확장해서 쓴다.

창 크기는 640×800 을 유지하고, 탭 콘텐츠가 넘치면 VScroll 을 쓴다(설정 탭과 같은 패턴). 긴 라벨은 모두 Wrapping.

## 14. 작업 규칙

- 브랜치는 develop 기준. 각 이슈는 자기 범위의 파일만 만진다. README/CHANGELOG 는 마지막에 한 번에 쓴다.
- `go vet ./...`, `go test ./...` (cgo: `PATH=/c/msys64/mingw64/bin:$PATH`, `CGO_ENABLED=1`) 통과 후 커밋.
- 텔레그램 API 는 테스트에서 `httptest.Server` 로 대체한다. 실제 봇 호출은 하지 않는다.
- 새 문자열은 ko/en 둘 다. GUI 는 `gui/i18n.go`, 서비스 템플릿은 `service/telegram/templates/{ko,en}/`.
