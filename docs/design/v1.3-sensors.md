# 설계: v1.3.0 PC 상태 감지 (카메라·마이크, 모니터, 오디오 출력)

v1.3.0에서 PC 쪽에 새로 붙는 상태 감지를 한곳에 모은다. 기능마다 절 하나씩이고, 각 절은 그 기능을 맡은 작업자가 쓴다.
공통 규칙은 v1.2.0([media-notify.md](media-notify.md))과 같다: 옵트인은 기본 꺼짐, 상태는 `/st/v1/status` 블록 + `features[]` + `<블록>.changed` 푸시, 계약은 `testdata/st-v1` golden.

## 카메라·마이크 사용 감지와 사용 중 종료 보호 (#143, 드라이버 #152)

### 감지

Windows는 앱이 카메라·마이크를 쓸 때마다 사용자별 동의 저장소에 시각을 남긴다.

```
HKCU\Software\Microsoft\Windows\CurrentVersion\CapabilityAccessManager\ConsentStore\
    {webcam,microphone}\<패키지 앱>                 LastUsedTimeStart / LastUsedTimeStop (FILETIME QWORD)
    {webcam,microphone}\NonPackaged\<exe 경로>
```

`LastUsedTimeStop == 0`이고 `LastUsedTimeStart != 0`인 항목이 하나라도 있으면 그 장치는 **사용 중**이다.

- 서비스(LocalSystem)는 HKCU가 자기 것이므로, 명령 대상 세션(`findUserSession`, 모든 명령이 따르는 그 세션)의 사용자 토큰에서 SID를 얻어 `HKU\<SID>\...`를 **읽기만** 한다.
- 하이브가 안 올라와 있거나(로그인한 사람 없음) 목록을 못 읽으면 `unknown`. 장치 키 자체가 없으면(한 번도 안 씀) `idle`.
- 3초마다 읽고(`privacyScanInterval`), 설정 저장 직후 한 번 더 읽는다. 두 장치 상태가 바뀔 때만 `privacy.changed`를 푸시한다. 옵션을 켜거나 끄는 것도 변화로 푸시한다.
- 키 이름(앱 정체)은 읽고 버린다. 상태·로그·알림 어디에도 앱 이름은 나가지 않는다.
- 코드: `service/privacy`(읽기·판정), `service/privacy_guard.go`(루프·보호), 설정 `internal/config/privacy.go`.

### 계약

설정(`config.json`):

```json
"privacy": { "enabled": false, "guard": "warn" }      // guard ∈ off | warn | block
```

`GET /st/v1/status` — `privacy.enabled`일 때만 키가 있다. `features[]`에 `"privacy"`.

```json
"privacy": { "camera": "in_use", "microphone": "idle", "since": "2026-10-01T20:45:00+09:00" }
```

- `camera`, `microphone`: `in_use` | `idle` | `unknown`
- `since`: 사용 중인 것이 있으면 그중 가장 이른 시작, 아니면 마지막 사용이 끝난 시각. 모르면 `""`.

푸시 `privacy.changed` — `data`는 status의 `privacy` 블록과 같은 JSON(`activity.changed`와 같은 방식). 옵션을 끄면 `data: null`이고 status에서 블록과 `features`의 `privacy`가 빠진다.

### 사용 중 종료 보호

대상: `shutdown` · `restart` · `suspend` · `hibernate`.

| 경로 | 보호 |
|---|---|
| SmartThings(`/st/v1/command`, 예전 `/{secret}/{command}` URL) | 예 |
| 텔레그램(확인 후 실행, `/now`, [바로 실행]) | 예 |
| WebUI(`/api/command` by=webui) | 예 |
| 예약(앱·WebUI·텔레그램·SmartThings 예약, 원격 유예 포함)이 실행되는 순간 | 예 |
| PC 앞 데스크톱 앱 · 트레이 · 토스트 버튼 | 아니오 |
| `forceshutdown` | 아니오(비상 탈출구) |

- `warn`(기본): 즉시 명령은 실행하고 알림(`remote.received` / `remote.grace_scheduled`)에 `in_use` 필드를 붙인다(텔레그램 문구 "⚠️ 카메라 사용 중", 유예 토스트에도 한 줄). 예약은 실행 시각에 사용 중이면 **한 번만** 유예 시간(`grace_seconds`)만큼 미루고 `privacy.extended` 알림을 보낸 뒤, 다음엔 실행한다.
- `block`: 실행하지 않는다. `/st/v1/command`와 WebUI는 `409 {"error":"device_in_use","devices":["camera"]}`, 예전 URL은 409 본문 한 줄, 텔레그램은 사유 문구로 답한다. 예약은 취소(`by: device_in_use`)하고 `privacy.blocked` 알림을 보낸다.
- 거절된 명령은 `last_command`에 기록하지 않는다.
- 판정 직전에 저장소를 한 번 더 읽어(최대 3초 늦은 값 대신) 판단한다.

### 실기 확인

- Windows 카메라 앱 · Teams/Zoom/Discord 통화를 켜고 끄며 3초 안에 `camera`/`microphone`이 바뀌는지(패키지 앱과 `NonPackaged` 둘 다).
- 잠금 상태 · RDP 세션 · 다른 사용자 전환에서 대상 사용자의 값이 나오는지, 로그아웃 시 `unknown`인지.
- 앱이 비정상 종료되면 `LastUsedTimeStop`이 0으로 남아 계속 사용 중으로 보일 수 있다(HASS.Agent 등에서 알려진 현상). 재현되면 프로세스 생존 확인 등 보정을 별도 이슈로.
