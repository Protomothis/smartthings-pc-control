# Changelog — SmartThings Edge 드라이버

허브 안에서 도는 Edge 드라이버(`edge/`)의 변경 이력입니다. 드라이버는 Windows 앱과 버전이 따로 돌고(`src/driver_version.lua`, 태그 `edge-vX.Y.Z`), 사용자는 GitHub 릴리스가 아니라 SmartThings 채널을 통해 자동으로 업데이트를 받습니다. Windows 서비스·트레이 앱의 이력은 [../CHANGELOG.md](../CHANGELOG.md)에 있습니다.

## [Unreleased]

> 아직 채널에 공개되지 않았습니다. 아래는 `edge-v1.0.0` 마일스톤에 쌓이는 변경입니다.

- **예약 시간 목록을 고르지 않고 닫을 때 나던 "네트워크 또는 서버 오류"를 고쳤습니다.** 목록을 닫을 때 앱이 보내는 현재 값은 프레젠테이션의 정수 변환을 거치지 않고 문자열로 나가는데, 정의는 정수를 요구해 클라우드가 거부하고 있었습니다. `schedule`의 `minutes`를 문자열 목록(`-1` `0`과 프리셋 열여섯)으로 다시 정의했습니다. 화면·프리셋·동작은 그대로입니다 (#91)
- 정의가 바뀌었으므로 capability id가 `pcDelay` → `pcDefer`(`numbersystem53811.pcdefer`)가 되고, 프로필은 `pc.v16`입니다. 기존 장치는 첫 `init`에서 자동으로 이전되고 예약 카드를 한 번 다시 칠합니다 (#91)
- 버전 줄이 PC가 꺼져 있어도 마지막으로 확인한 서비스 버전을 그대로 보여 줍니다. `v?`는 한 번도 응답받지 못한 PC에만 쓰입니다 (#92)
- **PC가 꺼지거나 켜지는 중에는 명령 목록이 `종료 진행 중…`·`켜는 중…`으로 바뀌고, 그동안 들어온 명령은 PC로 보내지 않습니다.** 상태 줄에 "종료 진행 중 · 끝난 뒤 다시 시도"가 잠깐 뜨고, 전환이 끝나면 목록이 저절로 다시 열립니다. 새로고침·예약 취소·스위치 켜기(= 유예 취소)는 그대로 통과합니다. 3일 뒤 종료 같은 긴 예약은 전환이 아니므로 아무것도 막지 않습니다 (#93)
- 명령 목록이 보여 줄 항목을 새 `supportedCommands` 속성에서 읽도록 했습니다. 전환 중에 항목이 실제로 사라지는지는 실기 확인 대기이고, 먹지 않아도 위의 문구와 드라이버 가드는 그대로 동작합니다 (#93)
- 정의가 바뀌었으므로 capability id가 `pcExec` → `pcRemote`(`numbersystem53811.pcremote`)가 되고, 프로필은 `pc.v17`입니다. 기존 장치는 첫 `init`에서 자동으로 이전되고 명령 카드를 한 번 다시 칠합니다 (#93)
