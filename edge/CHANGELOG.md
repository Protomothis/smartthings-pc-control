# Changelog — SmartThings Edge 드라이버

허브 안에서 도는 Edge 드라이버(`edge/`)의 변경 이력입니다. 드라이버는 Windows 앱과 버전이 따로 돌고(`src/driver_version.lua`, 태그 `edge-vX.Y.Z`), 사용자는 GitHub 릴리스가 아니라 SmartThings 채널을 통해 자동으로 업데이트를 받습니다. Windows 서비스·트레이 앱의 이력은 [../CHANGELOG.md](../CHANGELOG.md)에 있습니다.

## [Unreleased]

- **볼륨·음소거·미디어 제어가 생겼습니다.** 상세 화면에 재생·일시정지·정지, 이전·다음 곡, 볼륨 슬라이더, 음소거 토글이 SmartThings 표준 capability로 붙습니다(`mediaPlayback` · `mediaTrackControl` · `audioVolume` · `audioMute`). PC에 로그인한 사용자의 세션에서 동작하고 **서비스 v1.2.0이 필요**합니다. 옛 서비스이거나 로그인한 사용자가 없거나 PC에서 미디어 제어를 꺼 두었으면 명령을 보내지 않고 상태 줄에 `서비스 v1.2.0 필요` · `사용자 없음` · `미디어 제어 꺼짐`을 띄웁니다. 재생 상태(지금 재생 중인지)는 아직 보고하지 않습니다 (#107)
- 프로필이 `pc.v6`으로 올라갑니다. 아이콘 열 가지 × 배터리 유무의 스무 개 프로필(`pc.v6` · `pc-<style>.v6` · `pc-battery.v6` · `pc-<style>-battery.v6`)은 이제 템플릿 하나(`tools/profile-template.yml`)에서 `tools/gen-profiles.js`가 만들고, 테스트가 생성 결과와 파일이 같은지 지킵니다. 기존 장치는 첫 `init`에서 같은 아이콘의 v6으로 자동으로 옮겨지고 모든 줄이 다시 칠해집니다. 그 사이 Dev 채널에만 나갔던 `pc*.v2` · `pc*.v3` · `pc*.v4` · `pc*.v5`는 패키지 한도(655360바이트) 때문에 파일을 빼고 이름만 남겨, 그 장치도 같은 아이콘·같은 배터리 쪽의 v6으로 옮겨집니다 (#107, #108, #123)
- **프리셋을 실행할 수 있습니다.** 데스크톱 앱에 등록한 프리셋을 새 커스텀 capability `pcPreset`(`numbersystem53811.pcpreset`)의 목록에서 슬롯(`프리셋 1`…`프리셋 10`)으로 고르고, 이름은 `프리셋 목록` 줄(`1 게임 모드 · 2 방송 시작`)이 보여 줍니다. 루틴 동작도 있습니다. 원격은 슬롯 번호만 보내며, 비어 있는 슬롯은 보내지 않고 `프리셋 7 비어 있음`을 띄웁니다. 등록되지 않은 슬롯을 목록에서 숨기는 것은 실측 대기입니다 (#113)
- **감시하는 앱마다 장치가 생깁니다.** 데스크톱 앱에서 실행 중 앱 감지를 켜고(옵트인) 감시 목록에 앱을 넣으면, PC 장치 아래에 앱마다 장치(`Steam` 등, 프로필 `pc-app.v1`)가 생기고 그 장치가 `실행 중` / `꺼짐`을 보여 줍니다. 루틴 조건 "Steam의 실행 상태가 실행 중 / 꺼짐"으로 씁니다(새 커스텀 capability `pcApp`, `numbersystem53811.pcapp`). PC 장치의 `앱` 줄(새 `pcApps`, `numbersystem53811.pcapps`)은 실행 중인 것 중 **목록 맨 위의 앱**을 `Steam 실행 중 · 외 1개`처럼 말하고, 하나도 안 돌면 `없음`, 감지를 끄면 `꺼짐`, 옛 서비스면 `서비스 v1.2.0 필요`입니다. 목록에서 빼면 그 장치는 지워지고(그 장치를 쓰는 루틴은 깨집니다), 감지를 잠시 끄거나 PC가 꺼져 있을 때는 장치가 마지막 값을 그대로 지킵니다. 장치 이름은 앱에서 바꿔도 드라이버가 덮어쓰지 않습니다. 바뀌면 푸시로 바로 반영됩니다. 앞서 Dev 채널에만 있던 종류(게임 · 작업 …) 방식의 `pcActivity`는 이것으로 대체되어 공개되지 않습니다. 계정 소유자는 `./tools/create-capabilities.sh pcApps pcApp`으로 만들고 번역을 올립니다 (#114, #123)
- **잠들지 않기 스위치가 생겼습니다.** 장치에 `잠들지 않기` 컴포넌트가 붙고, 그 표준 스위치를 켜면 새 환경설정 `잠들지 않기 시간`(기본 60분, 0 = 끌 때까지) 동안 PC가 자동 절전하지 않습니다. 절전·종료 명령은 막지 않습니다. 루틴의 동작·조건으로 그대로 쓸 수 있고, PC 앱·텔레그램에서 바꿔도 푸시로 바로 따라옵니다 (#115)
- **노트북의 배터리가 보입니다.** 배터리가 있는 PC만 `배터리` 컴포넌트가 있는 같은 아이콘의 프로필(`pc-<style>-battery.v6`)로 옮겨지고, 표준 `battery`(잔량 %)·`powerSource`(전원 어댑터 · 배터리)가 보입니다. 데스크톱에는 빈 카드가 생기지 않습니다. 한 번 튀는 값으로 프로필이 오가지 않도록 상태 두 번이 연달아 같아야 옮깁니다. 루틴 조건 "배터리 20% 이하"를 쓸 수 있습니다 (#116)
- **PC에 메시지를 보낼 수 있습니다.** 상세 화면과 루틴 동작의 **PC에 메시지 보내기**에 문구를 넣으면 PC에 토스트가 뜹니다. 새 커스텀 capability `pcToast`(`numbersystem53811.pctoast`, 명령 `send(text)`와 속성 `lastMessage`)입니다 — 표준 `notification`은 앱이 삼성의 번역("텍스트 표시")으로 보여 주고 장치 쪽에서 바꿀 방법이 없어서 우리 문구를 쓰는 capability로 만들었습니다. 입력 줄은 마지막으로 보낸 문구를 보여 주고(처음엔 `없음`), 보낼 때마다 그 줄이 답하므로 회전 표시가 바로 끝납니다. 문구는 200자에서 잘리고, 제어 문자는 지웁니다. 보내면 메시지 줄에 `PC에 메시지를 보냈습니다`, 보내지 못하면 `PC 알림 꺼짐` · `사용자 없음` · `잠시 후 다시` · `서비스 v1.2.0 필요`를 띄웁니다. 계정 소유자는 `./tools/create-capabilities.sh pcToast`로 한 번 만들고 번역을 올립니다 (#108)
- **지금 재생 중인 곡이 보입니다.** 미디어 묶음 맨 위에 표준 `audioTrackData`(제목 · 아티스트 · 앨범)가 붙고, 재생/일시정지 버튼이 `mediaPlayback.playbackStatus`로 실제 상태를 따릅니다. 곡 정보는 PC에서 재생 정보 공유를 켰을 때만 오고(옵트인), 아무것도 재생하지 않으면 `재생 중인 미디어 없음`, 공유를 끄면 `재생 정보 꺼짐`입니다. 바뀌면 푸시로 바로 반영됩니다. 상세 화면은 상태·조작 카드 다음에 미디어 묶음(곡 정보 → 재생 → 곡 이동 → 볼륨 → 음소거), 그다음 프리셋 · 앱 · PC에 메시지 보내기 순입니다. 미디어 묶음을 별도 컴포넌트로 뺀 배치는 생성기의 `--media-component`로 만들어 Dev 채널에서 비교합니다 (#118)
- **명령을 연달아 보내면 상태가 앱에 반영되지 않던 문제(이벤트 과다)를 고쳤습니다.** 드라이버가 폴링·명령마다 줄 전부를 다시 내보내 장치의 이벤트 한도를 넘기면, 그 뒤 이벤트가 한동안 모두 버려지고 음소거 같은 줄이 틀린 값에 굳었습니다. 이제 바뀐 줄과 명령의 응답만 보내고, 몰아친 명령의 후속 폴링은 하나로 합치며(전원·예약·취소 명령 포함), **모든 줄을 폴링마다 몇 개씩 돌아가며 다시 보내 10분 안에 한 바퀴 맞춥니다**(기본 30초 주기에서 폴링마다 3개, 앱 장치도 10분에 한 번) — 한도 때문에 잃은 값이 허브에 굳어 버려도 몇 분 안에 저절로 바로잡힙니다. 허브·드라이버가 다시 시작할 때의 첫 폴링은 바뀐 줄과 전원·음소거·볼륨·재생·잠들지 않기 줄만 보내고(약 40개 → 6개), 프로필이 바뀐 뒤의 다시 칠하기는 줄마다 한 번만, 한꺼번에가 아니라 5초마다 9개씩 나눠 보내며(이전 시 약 220개 → 60개, 가장 바쁜 10초 48개 → 18개, 모든 줄 20초 안 — 전원·상태 요약·앱 요약 줄이 맨 먼저), 폴링 주기 같은 환경설정만 바꿀 때는 다시 칠하지 않습니다. 개발 허브의 v5 → v6 이전에서 한꺼번에 나간 약 49개 중 `앱` 요약 줄이 클라우드에 닿지 않고, 새로 고침과 드라이버 재시작 뒤에도 빈 채로 남았던 것이 이 변경의 계기입니다 (#129)
- 프리셋을 실행한 뒤 목록이 다시 고를 수 있게 돌아오기까지 최대 30초 넘게 걸리던 것을 몇 초로 줄였습니다. `프리셋 3 실행함`은 5초 뒤 타이머가 `프리셋 선택…`으로 되돌리고, 다음 폴링을 기다리지 않습니다 (#113)
- (내부) 패키지는 주석을 빈 줄로 바꾼 `build/edge/`(`node tools/build.js`)로 만들어 크기가 약 절반이 되고(564 KB → 340 KB, 허브 로그의 줄 번호는 그대로), 드라이버 코드는 기능 변경 없이 `handlers/` · `device/` · `model/`로 나뉩니다 (#129)
- WoL이 꺼져 있다는 안내가 데스크톱 앱의 바뀐 탭 이름을 따라 `… · SmartThings 탭 확인`(`check the SmartThings tab`)이 됐습니다. 예전의 네트워크 탭입니다 (#128)

## [1.0.1] - 2026-09-28

- **장치 아이콘을 바꿀 수 있습니다.** 환경설정에 `아이콘`이 생겼습니다 — 기타(기본) · 모니터 · 스위치 · 플러그 · TV · 프로젝터 · 네트워크 · 허브 · 홈시어터 · 리모컨. 앱은 아이콘을 장치의 카테고리로 정하는데 기본 카테고리인 `기타`는 앱에서 아이콘을 고를 수 없어서, 값마다 카테고리만 다른 프로필(`pc-monitor.v1` 등)을 두고 설정을 바꾸면 드라이버가 장치를 그 프로필로 옮깁니다. 화면·설정·자동화는 그대로이고 장치를 다시 추가할 필요가 없으며, 옮긴 직후 비는 줄은 드라이버가 곧 다시 채웁니다 (#100)
- 대시보드 타일이 전원 상태를 `절전 (Sleeping)`·`종료 대기 (Shutting down)`처럼 문구로 보여 주도록, 타일 문구를 상세 화면의 전원 상태 줄과 같은 일곱 값으로 고정했습니다. 토글은 그대로 스위치입니다. 기존 장치의 타일에 실제로 뜨는지는 Dev 채널 실측 대기입니다 (#101)
- 상태 줄이 연결된 PC의 가동 시간을 `연결됨 · 3일 2시간`처럼, 응답하지 않는 PC가 마지막으로 응답한 때를 `응답 없음 · 마지막 확인 12분 전`처럼 보여 줍니다. 마지막 확인 시각은 허브가 다시 시작해도 남습니다. 한 번도 응답받지 못한 PC와 시크릿·버전 불일치는 예전 문구 그대로이고, 줄이 24자를 넘으면 WoL 꺼짐 안내가 가동 시간보다 먼저입니다 (#102)

## [1.0.0] - 2026-09-26

**첫 공개 버전입니다.** 커스텀 capability 여섯 — `pcPower`(전원 상태) · `pcRemote`(명령 실행) · `pcDefer`(예약) · `pcUser`(세션, 옵트인) · `pcInfo`(연결·업데이트·WoL·안내) · `pcVersion`(버전 줄) — 으로 상세 화면을 그리며, 프로필은 `pc.v1`입니다.

> 채널(`Protomothis`)로 나가는 첫 릴리스입니다. 아래는 `edge-v1.0.0` 마일스톤에 쌓인 변경입니다.

- **예약 시간 목록을 고르지 않고 닫을 때 나던 "네트워크 또는 서버 오류"를 고쳤습니다.** 목록을 닫을 때 앱이 보내는 현재 값은 프레젠테이션의 정수 변환을 거치지 않고 문자열로 나가는데, 정의는 정수를 요구해 클라우드가 거부하고 있었습니다. `schedule`의 `minutes`를 문자열 목록(`-1` `0`과 프리셋 열여섯)으로 다시 정의했습니다. 화면·프리셋·동작은 그대로입니다 (#91)
- 정의가 바뀌었으므로 capability id가 `pcDelay` → `pcDefer`(`numbersystem53811.pcdefer`)가 되었습니다. 공개되는 것은 이 id이므로 이전할 장치는 없습니다 (#91)
- 버전 줄이 PC가 꺼져 있어도 마지막으로 확인한 서비스 버전을 그대로 보여 줍니다. `v?`는 한 번도 응답받지 못한 PC에만 쓰입니다 (#92)
- **장치의 모델이 PC 식별자를 담습니다.** 앱의 *장치 정보*에서 `PC Control · 58bff996`처럼 보이고, 앞 8자는 Windows 앱이 보여 주는 이 PC의 ID와 같은 값입니다. 장치 이름(`DESKTOP-ABC 컴퓨터`)은 그대로이며, 기존 장치는 다음 상태 조회에 성공할 때 한 번 갱신됩니다 (#94)
- **검색이 아무 PC도 찾지 못하면 이제 아무 장치도 만들지 않습니다.** 예전에는 `PC Control (set IP in settings)` 장치가 하나 생겼지만, 그것은 "PC가 꺼져 있다"는 사실을 장치로 남기는 일이었고 다음 검색까지 막았습니다. 장치 추가는 검색이 유일한 경로이므로 **검색을 누르기 전에 PC와 PC Control이 켜져 있어야 합니다.** 주소를 고정하는 `PC IP 주소` 환경설정은 그대로입니다 (#94)
- **PC가 꺼지거나 켜지는 중에는 명령 목록이 `종료 진행 중…`·`켜는 중…`으로 바뀌고, 그동안 들어온 명령은 PC로 보내지 않습니다.** 상태 줄에 "종료 진행 중 · 끝난 뒤 다시 시도"가 잠깐 뜨고, 전환이 끝나면 목록이 저절로 다시 열립니다. 새로고침·예약 취소·스위치 켜기(= 유예 취소)는 그대로 통과합니다. 막히는 구간은 **PC에 설정된 유예 길이**를 그대로 따르므로, 유예를 5분으로 잡아 두었다면 그 5분이 해당합니다. 3일 뒤 종료 같은 긴 예약은 전환이 아니므로 아무것도 막지 않습니다 (#93)
- **WoL은 이제 PC가 고른 랜카드로 보냅니다.** 랜카드가 여럿인 PC(이더넷 + Wi-Fi, Hyper-V·VPN 가상 어댑터)에서 드라이버가 "WoL이 켜진 첫 어댑터"를 골라 엉뚱한 MAC으로 깨우려 하던 것을, 데스크톱 앱 네트워크 탭의 **WoL 어댑터** 선택을 그대로 따르도록 바꿨습니다. `MAC 주소` 환경설정을 채워 넣었다면 그 값이 계속 최우선이고, 아직 어댑터를 고르지 않는 옛 서비스에서는 예전 규칙 그대로 동작합니다. "WoL 꺼짐" 안내도 고른 어댑터 하나를 기준으로 하며, 상태 줄과 메시지 줄이 `연결됨 · WoL 꺼짐 (이더넷)`처럼 어느 랜카드를 열어야 하는지 이름을 댑니다 (#97)
- 명령 목록이 보여 줄 항목을 새 `supportedCommands` 속성에서 읽도록 했습니다. 전환 중에 항목이 실제로 사라지는지는 실기 확인 대기이고, 먹지 않아도 위의 문구와 드라이버 가드는 그대로 동작합니다 (#93)
- 정의가 바뀌었으므로 capability id가 `pcExec` → `pcRemote`(`numbersystem53811.pcremote`)가 되었습니다. 공개되는 것은 이 id이므로 이전할 장치는 없습니다 (#93)
- 프로필 이름을 `pc.v1`로 초기화했습니다. 개발 중 쌓인 `pc.v2`…`pc.v17`은 어느 사용자의 허브에도 간 적이 없어 패키지에서 뺐습니다. 화면이 바뀌면 다음 버전은 `pc.v2`이고, 기존 장치는 그때부터 첫 `init`에서 자동으로 이전됩니다 (#90)
