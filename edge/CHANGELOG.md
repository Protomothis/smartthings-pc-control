# Changelog — SmartThings Edge 드라이버

허브 안에서 도는 Edge 드라이버(`edge/`)의 변경 이력입니다. 드라이버는 Windows 앱과 버전이 따로 돌고(`src/driver_version.lua`, 태그 `edge-vX.Y.Z`), 사용자는 GitHub 릴리스가 아니라 SmartThings 채널을 통해 자동으로 업데이트를 받습니다. Windows 서비스·트레이 앱의 이력은 [../CHANGELOG.md](../CHANGELOG.md)에 있습니다.

## [Unreleased]

드라이버 1.1.0입니다. 아래 새 기능은 PC Control 서비스 **v1.2.0**이 필요합니다. 그보다 오래된 서비스에서는 해당 줄이 `서비스 v1.2.0 필요`를 띄우고 명령을 보내지 않습니다. 기존 기능은 지금처럼 v1.1.0 이상에서 동작합니다.

### 업그레이드 안내

- 기존 장치는 첫 `init`에서 같은 아이콘의 새 프로필(`pc*.v7`)로 저절로 옮겨집니다. 다시 추가할 필요가 없고, 빈 줄은 30초 안에 채워집니다 (#107, #123, #129)
- 노트북은 배터리 카드가 있는 같은 아이콘의 프로필로 옮겨집니다. 데스크톱에는 빈 배터리 카드가 생기지 않습니다 (#116)
- Dev 채널 시험판에만 있던 기능(표준 텍스트 표시 · 음성 합성, `pcMessage` · `pcNotify` · `pcActivity`, 앱마다 만들던 장치와 `pcApps` · `pcApp`)은 공개되지 않습니다. 공개 채널 사용자는 할 일이 없습니다. 시험판이 만든 앱 장치는 드라이버가 지우고, 지우지 못하면 앱에서 직접 삭제합니다 (#108, #123)

### 추가

- **미디어 묶음** — 상세 화면에 곡 정보, 재생 · 일시정지 · 정지, 이전 · 다음 곡, 볼륨 슬라이더, 음소거가 생깁니다. SmartThings 표준 capability라 루틴에도 그대로 씁니다 (#107, #118)
- 재생 버튼은 PC의 실제 재생 상태를 따릅니다. 곡 정보는 PC에서 재생 정보 공유를 켰을 때만 오고, 끄면 `재생 정보 꺼짐`입니다 (#118)
- 로그인한 사용자가 없거나 PC에서 미디어 제어를 껐으면 명령을 보내지 않고 상태 줄에 `사용자 없음` · `미디어 제어 꺼짐`을 띄웁니다 (#107)
- **프리셋** — PC 앱에 등록한 프리셋을 목록(`프리셋 1`…`프리셋 10`)과 루틴 동작에서 실행합니다. `프리셋 목록` 줄이 슬롯의 이름을 보여 줍니다 (#113)
- 프리셋을 실행하면 목록이 5초 동안 `프리셋 3 실행함`을 보였다가 돌아옵니다. 비어 있는 슬롯은 보내지 않고 `프리셋 7 비어 있음`을 띄웁니다 (#113)
- **감시 목록** — PC 앱에서 실행 중 앱 감지를 켜면 PC 장치의 `감시 목록` 카드에 감시 중인 앱(최대 5개)이 번호와 함께 보입니다: `Steam 실행 중 · 외 1개`, `1 Steam · 3 OBS`, `감시 1`…`감시 5` (#123)
- 루틴 조건은 PC 장치의 `감시 1`…`감시 5`가 `실행 중` / `꺼짐`일 때입니다. 번호가 작을수록 우선하고, 빈 번호는 `비어 있음`입니다 (#123)
- 감지를 잠시 끄거나 PC가 꺼져 있을 때는 마지막 값을 지킵니다. 목록을 고친 직후에는 실행 중이던 번호를 한 번 더 기다렸다가 바꿉니다 (#123)
- **PC에 메시지 보내기** — 상세 화면이나 루틴 동작에서 문구(200자까지)를 넣으면 PC 화면에 알림이 뜹니다. 그 줄은 마지막으로 보낸 문구를 보여 줍니다 (#108)
- 메시지를 보내지 못하면 메시지 줄이 이유를 말합니다: `PC 알림 꺼짐` · `사용자 없음` · `잠시 후 다시` (#108)
- **잠들지 않기** — `잠들지 않기` 카드의 스위치를 켜면 새 환경설정 `잠들지 않기 시간`(기본 60분, 0 = 끌 때까지) 동안 PC가 자동 절전하지 않습니다 (#115)
- 잠들지 않기는 표준 스위치라 루틴의 동작 · 조건으로 씁니다. PC 앱이나 텔레그램에서 바꿔도 바로 따라옵니다 (#115)
- **노트북 배터리** — 배터리가 있는 PC는 `배터리` 카드에 잔량(%)과 전원 공급원을 보여 줍니다. 루틴 조건 "배터리 20% 이하"를 쓸 수 있습니다 (#116)

### 변경

- 드라이버가 바뀐 줄과 명령의 응답만 보냅니다. 연달아 보낸 명령 뒤 줄이 틀린 값에 굳던 일이 줄고, 잃은 값은 10분 안에 저절로 바로잡힙니다 (#129)
- WoL이 꺼져 있다는 안내가 PC 앱의 새 탭 이름을 따라 `… · SmartThings 탭 확인`이 됐습니다 (#128)

### 내부

- 현재 프로필 스무 개는 템플릿 하나에서 `tools/gen-profiles.js`가 만들고, 테스트가 생성 결과와 파일이 같은지 확인합니다 (#107)
- 패키지는 주석을 뗀 `build/edge/`(`node tools/build.js`)로 만들어 크기가 약 절반입니다. 허브 로그의 줄 번호는 그대로입니다 (#129)
- 드라이버 코드를 기능 변경 없이 `handlers/` · `device/` · `model/`로 나눴습니다 (#129)
- 새 커스텀 capability `pcPreset` · `pcWatch` · `pcToast`는 계정 소유자가 `tools/create-capabilities.sh`로 만듭니다 (#108, #113, #123)

## [1.0.1] - 2026-09-28

- **장치 아이콘을 바꿀 수 있습니다.** 환경설정에 `아이콘`이 생겼습니다 — 기타(기본) · 모니터 · 스위치 · 플러그 · TV · 프로젝터 · 네트워크 · 허브 · 홈시어터 · 리모컨. 앱은 아이콘을 장치의 카테고리로 정하는데 기본 카테고리인 `기타`는 앱에서 아이콘을 고를 수 없어서, 값마다 카테고리만 다른 프로필(`pc-monitor.v1` 등)을 두고 설정을 바꾸면 드라이버가 장치를 그 프로필로 옮깁니다. 화면·설정·자동화는 그대로이고 장치를 다시 추가할 필요가 없으며, 옮긴 직후 비는 줄은 드라이버가 곧 다시 채웁니다 (#100)
- 대시보드 타일이 전원 상태를 `절전 (Sleeping)`·`종료 대기 (Shutting down)`처럼 문구로 보여 주도록, 타일 문구를 상세 화면의 전원 상태 줄과 같은 일곱 값으로 고정했습니다. 토글은 그대로 스위치입니다. 기존 장치의 타일에 실제로 뜨는지는 Dev 채널 실측 대기입니다 (#101)
- 상태 줄이 연결된 PC의 가동 시간을 `연결됨 · 3일 2시간`처럼, 응답하지 않는 PC가 마지막으로 응답한 때를 `응답 없음 · 마지막 확인 12분 전`처럼 보여 줍니다. 마지막 확인 시각은 허브가 다시 시작해도 남습니다. 한 번도 응답받지 못한 PC와 시크릿·버전 불일치는 예전 문구 그대로이고, 줄이 24자를 넘으면 WoL 꺼짐 안내가 가동 시간보다 먼저입니다 (#102)

## [1.0.0] - 2026-09-26

**첫 공개 버전입니다.** 커스텀 capability 여섯 — `pcPower`(전원 상태) · `pcRemote`(명령 실행) · `pcDefer`(예약) · `pcUser`(세션, 옵트인) · `pcInfo`(연결·업데이트·WoL·안내) · `pcVersion`(버전 줄) — 으로 상세 화면을 그리며, 프로필은 `pc.v1`입니다.

> 채널(`Protomothis`)로 나가는 첫 릴리스입니다. 아래는 `edge-v1.0.0` 마일스톤에 쌓인 변경입니다.

- **예약 시간 목록을 고르지 않고 닫을 때 나던 "네트워크 또는 서버 오류"를 고쳤습니다.** 목록을 닫을 때 앱이 보내는 현재 값은 프레젠테이션의 정수 변환을 거치지 않고 문자열로 나가는데, 정의는 정수를 요구해 클라우드가 거부하고 있었습니다. `schedule`의 `minutes`를 문자열 목록(`-1` `0`과 프리셋 열여섯)으로 다시 정의했습니다. 화면·프리셋·동작은 그대로입니다 (#91)
- 정의가 바뀌었으므로 capability id가 `pcDelay` → `pcDefer`(`numbersystem53811.pcdefer`)가 되었습니다. 공개되는 것은 이 id이므로 이전할 장치는 없습니다 (#91)
- 버전 줄이 PC가 꺼져 있어도 마지막으로 확인한 서비스 버전을 그대로 보여 줍니다. `v?`는 한 번도 응답받지 못한 PC에만 쓰입니다 (#92)
- **장치의 모델이 PC 식별자를 담습니다.** 앱의 *장치 정보*에서 `PC Control · 58bff996`처럼 보이고, 앞 8자는 Windows 앱이 보여 주는 이 PC의 ID와 같은 값입니다. 장치 이름(`DESKTOP-ABC 컴퓨터`)은 그대로이며, 기존 장치는 다음 상태 조회에 성공할 때 한 번 갱신됩니다 (#94)
- **검색이 아무 PC도 찾지 못하면 이제 아무 장치도 만들지 않습니다.** 예전에는 `PC Control (set IP in settings)` 장치가 하나 생겼지만, 그것은 "PC가 꺼져 있다"는 사실을 장치로 남기는 일이었고 다음 검색까지 막았습니다. 장치 추가는 검색이 유일한 경로이므로 **검색을 누르기 전에 PC와 PC Control이 켜져 있어야 합니다.** 주소를 고정하는 `PC IP 주소` 환경설정은 그대로입니다 (#94)
- **PC가 꺼지거나 켜지는 중에는 명령 목록이 `종료 진행 중…`·`켜는 중…`으로 바뀌고, 그동안 들어온 명령은 PC로 보내지 않습니다.** 상태 줄에 "종료 진행 중 · 끝난 뒤 다시 시도"가 잠깐 뜨고, 전환이 끝나면 목록이 저절로 다시 열립니다. 새로고침·예약 취소·스위치 켜기(= 유예 취소)는 그대로 통과합니다. 막히는 구간은 **PC에 설정된 유예 길이**를 그대로 따르므로, 유예를 5분으로 잡아 두었다면 그 5분이 해당합니다. 3일 뒤 종료 같은 긴 예약은 전환이 아니므로 아무것도 막지 않습니다 (#93)
- **WoL은 이제 PC가 고른 랜카드로 보냅니다.** 랜카드가 여럿인 PC(이더넷 + Wi-Fi, Hyper-V·VPN 가상 어댑터)에서 드라이버가 "WoL이 켜진 첫 어댑터"를 골라 엉뚱한 MAC으로 깨우려 하던 것을, 데스크톱 앱 네트워크 탭의 **WoL 어댑터** 선택을 그대로 따르도록 바꿨습니다. `MAC 주소` 환경설정을 채워 넣었다면 그 값이 계속 최우선이고, 아직 어댑터를 고르지 않는 옛 서비스에서는 예전 규칙 그대로 동작합니다. "WoL 꺼짐" 안내도 고른 어댑터 하나를 기준으로 하며, 상태 줄과 메시지 줄이 `연결됨 · WoL 꺼짐 (이더넷)`처럼 어느 랜카드를 열어야 하는지 이름을 댑니다 (#97)
- 명령 목록이 보여 줄 항목을 새 `supportedCommands` 속성에서 읽도록 했습니다. 전환 중에 항목이 실제로 사라지는지는 실기 확인 대기이고, 먹지 않아도 위의 문구와 드라이버 가드는 그대로 동작합니다 (#93)
- 정의가 바뀌었으므로 capability id가 `pcExec` → `pcRemote`(`numbersystem53811.pcremote`)가 되었습니다. 공개되는 것은 이 id이므로 이전할 장치는 없습니다 (#93)
- 프로필 이름을 `pc.v1`로 초기화했습니다. 개발 중 쌓인 `pc.v2`…`pc.v17`은 어느 사용자의 허브에도 간 적이 없어 패키지에서 뺐습니다. 화면이 바뀌면 다음 버전은 `pc.v2`이고, 기존 장치는 그때부터 첫 `init`에서 자동으로 이전됩니다 (#90)
